### Migration A2: `20260206151715_v1.3_phase_a2_create_reconcile_helper.sql`

**创建 Helper**:
- `match_participant_reconcile_status(p_mp_id uuid)` — 同步 status

**逻辑**:
1. 如果 `status = 'removed'` → 不操作（terminal check）
2. 如果 `guest_id IS NOT NULL`:
   - `org_approved_at IS NOT NULL` → `status = 'confirmed'`
   - Else → `status = 'pending'`
3. 如果 `user_id IS NOT NULL`:
   - `user_accepted_at IS NOT NULL AND org_approved_at IS NOT NULL` → `status = 'confirmed'`
   - Else → `status = 'pending'`

**Idempotency**: ✅ 多次调用结果一致

### Migration A3: `20260206151716_v1.3_phase_a3_backfill_existing_data.sql`

**数据回填策略**:

| 现有状态 | join_method | user_accepted_at | org_approved_at | 推理 |
|---------|-------------|-----------------|----------------|------|
| confirmed (user) | any | confirmed_at | confirmed_at | 双边都已确认 |
| confirmed (guest) | any | N/A | confirmed_at | Guest 只需 ORG |
| pending | invited | NULL | created_at | Invite = ORG 预批准 |
| pending | requested | created_at | NULL | Request = User 已接受 |
| removed | invited | NULL | created_at | User declined |
| removed | requested | created_at | NULL | ORG rejected |

**removed_by 推断**:
- `invited + removed` → `removed_by = user_id`（user declined）
- `requested + removed` → `removed_by = organizer_id`（ORG rejected）
- `confirmed + removed` → `removed_by = user_id`（assume withdrawal）
- `guest + removed` → `removed_by = organizer_id`

**Reconcile 验证**:
- ✅ 对所有 non-removed participants 调用 reconcile
- ✅ 验证 confirmed 状态的字段一致性
